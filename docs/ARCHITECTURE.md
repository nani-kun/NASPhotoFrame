# 运行架构与故障策略

主线程只创建 UIKit 对象、切换 `UIImageView` 和处理计时器。其余工作流如下：

```text
定时器 / 回到前台
        |
        v
scanQueue（串行） -> SMB2/3 递归枚举 -> 一次事务更新 SQLite 快照
        |                                      |
        +-------------- 扫描完成通知 ----------+

播放器 -> downloadQueue（串行） -> 检查缓存 -> SMB 下载 -> ImageIO 降采样
                                               |
                                               v
                                         主线程交叉淡入
```

扫描和下载使用不同后台队列：大目录扫描不会占用主线程，也不会阻止已经缓存的照片继续切换。每次 SMB 操作使用独立连接，避免 NAS 重启、路由器换租约或长时间 idle 后留下失效会话。

索引替换具有“成功才提交”语义。连接失败或任何目录枚举失败时不会删除旧索引，因此离线期间仍可播放缓存。新索引提交后，会在下载队列中删除所有未被新索引引用的缓存，保证 NAS 端删除的照片也从 iPad 删除。下载先写入 `.part`，完成后原子移动为正式缓存文件，断电不会把半张照片当成有效缓存。

当前版本有意不实现系统后台执行：永久相框正常情况下始终位于前台，而 iOS 8 的普通应用后台时间不能保证“每几小时”运行。应用重新进入前台时会根据上次成功扫描时间补扫。
